# Sabatina do plano

Entreviste o usuário sem trégua sobre cada aspecto do plano, até vocês dois chegarem a um entendimento comum.

## Como conduzir

1. **Ache o plano.** Se o usuário indicou um arquivo ou colou o texto, use isso. Se não, procure no repositório (README, docs, issues, histórico de commits) e reconstrua o plano a partir do código. Diga em uma ou duas linhas de onde tirou o plano.
2. **Percorra a árvore de decisões.** Comece pelas decisões mais fundamentais (objetivo, público, critério de sucesso) e só depois desça para as que dependem delas (produto, monetização, conteúdo, técnica, lançamento). Resolva as dependências entre as decisões uma de cada vez.
3. **Uma pergunta por vez.** Nunca mande uma lista de perguntas. Espere a resposta antes de seguir.
4. **Sempre dê a sua resposta recomendada**, com o motivo em poucas linhas, para o usuário poder só concordar, discordar ou corrigir.
5. **Se o código responde, não pergunte.** Quando a resposta puder ser encontrada explorando o repositório, explore em vez de perguntar, e use o que achou para fazer uma pergunta mais afiada.
6. **Aponte contradições e lacunas** entre o que o usuário diz e o que o código ou as respostas anteriores mostram. Não aceite respostas vagas: peça um número, um prazo ou um critério.
7. **Mantenha um registro** das decisões já tomadas e cite-as quando forem relevantes para a pergunta seguinte.

## Quando terminar

Quando os ramos principais estiverem resolvidos, ou quando o usuário pedir, faça um resumo com:
- as decisões tomadas;
- as questões ainda em aberto;
- os riscos principais;
- os próximos passos concretos.

Escreva no idioma do usuário.
